# Snowflake backends: Cortex Sense scenarios

The three Genie One scenarios (docs/databricks-metric-views-backend.md) repeated on Snowflake. The BIRD agent
(Sonnet 5) never writes SQL: it hands every question to a Cortex Agent grounded in the task database's Cortex
Sense context and submits the SQL that agent ran. Data, roles, semantic views and contexts are built by
`bird-snowflake-models`.

| # | Backend | Role | What the role reads | State |
|---|---|---|---|---|
| 1 | `sf_cortex_sense_raw` | `BIRD_S1` | the 244 base tables of `BIRD_BENCH` | needs the role's token |
| 2 | `sf_cortex_sense_coco_views` | `BIRD_S2` | base tables + 114 semantic views in `BIRD_SENSE.COCO_<DB>` | run 2026-11-22/23, n=3; contexts `BIRD_BENCH_<DB>_COCO_V3` (no query history) |
| 3 | `sf_cortex_sense_atscale_views` | `BIRD_S3` | base tables + 119 semantic views generated from the AtScale SML models in `BIRD_SENSE.ATSCALE_<DB>` | views and contexts `BIRD_BENCH_<DB>_ATSCALE` built 2026-11-23 |
| - | `sf_cortex_sense_smoke` | `BIRD_SENSE_PILOT` | everything the build role reads | wiring tests only, never scored |

## Pieces

- `system_agent/tools_cortex_sense.py`: `ask_cortex`. One inline `POST /api/v2/cortex/agent:run` per call with a
  single declared tool, `cortex_sense`, bound to the database's context (`context` in the domain config); the
  platform adds `system_execute_sql`, which runs as the caller's role on `SNOWFLAKE_WAREHOUSE`. Orchestration
  model `auto` (`agent_model`). No instructions are sent to the Cortex Agent. Cost 1 coin, 0.5 when no statement
  returned rows.
- Conversation: the API call is stateless here, so each call replays the task's earlier turns as text (the user's
  words, then the agent's answer and the SQL it settled on). Retrieved documents are not replayed. Genie One kept
  its conversation server-side; this is the nearest equivalent without agent threads.
- `shared/snowflake_sql.py`: SQL API v2 client with typed rows; `shared/snowflake_auth.py`: a token variable holds
  the PAT or `file:<path>`.
- Grading (`db_environment/server.py`, `executor: snowflake`): the submission is re-executed read-only as the same
  role and its rows compared with the gold SQL's rows from Postgres, as on Databricks. A statement that reads
  outside `BIRD_BENCH.<DB>` (for example the old lower-case `BIRD` database, which PUBLIC can read) is refused and
  audited as a routing miss.
- `config/environment_backends.snowflake_vs_0910.yaml` is generated by `scripts/gen_snowflake_backends.py` from
  the Genie raw-data block: same instruction, tool words rewritten.
- `scripts/run_snowflake_scenario.sh <1|2|3|smoke>`: preflight as the scenario's role (role matches the token, no
  secondary roles, 244 tables, the right semantic views or none, build inputs unreadable, 22 contexts, a lookup
  and an agent run), then the run and the comparison with the 2026-09-10 AtScale sweep.

## .env

```
SNOWFLAKE_HOST=https://<org>-<account>.snowflakecomputing.com
SNOWFLAKE_WAREHOUSE=BIRD_SENSE_WH
SNOWFLAKE_TOKEN_S1=file:~/.snowflake/bird_s1.pat      # one PAT per run role
SNOWFLAKE_TOKEN_PILOT=file:~/.snowflake/bird_sense.pat
```

## Verified 2026-11-20 (smoke backend, solar_panel)

Three task runs end to end: 2 passed both phases, 1 failed phase 1. Coins, the 0.5 refund for a queryless
turn, routing lines and the grading audit all behave as on Databricks.

## Known gaps

- `compare_vs_baseline_runs.py` labels the arm "Databricks" and "metric views"; the numbers are right.
- The per-database and workbook-tab scripts (`genie_one_by_db.py`, `build_databricks_scenario_tab.py`) read
  `ask_genie` log lines and need an `ask_cortex` variant.
- When asked for "the final SQL", the Cortex Agent can answer with SQL in text without running it; the BIRD agent
  may then submit SQL that was never executed by Cortex.
- An unrelated Streamlit query document (`STREAMLIT:b5606dd1...`) is returned by every context lookup.
